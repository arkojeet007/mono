# Licensing

Koru is licensed under the **[Mozilla Public License 2.0](../LICENSE)**, and
contributions come in under it too (see [CONTRIBUTING.md](../CONTRIBUTING.md)). This page says what that covers in
this tree, what it does not, and how the headers are kept true.
[THIRD-PARTY.md](THIRD-PARTY.md) is the audit of everything we did not write.

## Why MPL-2.0

MPL-2.0 is copyleft **per file**. A change to a Koru file that someone
distributes must be published under MPL-2.0. A file of their own placed beside
ours can be under any license, open or proprietary, in what MPL calls a
"Larger Work" (section 3.3). That fits the shape of the project:

- The app, local-first storage, peer-to-peer sync and the shared crates are
  open, and improvements to them stay open.
- The hosted Koru Cloud services link those shared crates from separate,
  proprietary files, which MPL permits without a CLA.

MPL-2.0 is compatible with the permissive licenses of our dependencies, and with
the MPL-2.0 crates among them.

## Headers

`scripts/checks/spdx-headers.py` inserts the header and `--check` lists what is
missing. It is idempotent, so run it after adding files or after a merge. Its
exclusions are rules, written at the top of the script:

- `third-party/`, `contracts/gen/`, and anything `@generated`.
- Non-Rust files under `fixtures/` or `testdata/`. A test reads them as bytes.
- **SQL.** sqlx stores a checksum of every applied migration. Changing even a
  comment in one makes every existing database refuse to migrate. Migrations are
  covered by the root `LICENSE` instead.
- Everything outside the script's roots — `docs/`, for one, which is prose.

The header goes after anything that must stay first: a shebang, a Python
encoding line, `// swift-tools-version`, `@echo off`, or a UTF-8 BOM. It is
followed by a blank line so it never joins the doc comment or docstring below it.

**Existing notices are never touched.** The script only prepends, and it skips a
file that already names an SPDX identifier. The Gradle wrapper (`gradlew`,
`gradlew.bat`, Apache-2.0, "the original authors") is fetched, not committed,
so the script never sees it.

## In a release

Every package carries `LICENSE`, `NOTICE` and `THIRD-PARTY-NOTICES.txt` in its
data root (beside the executables on Windows, in `Contents/Resources/` on
macOS). They are `koru_update::RELEASE_LEGAL`, so publish-time validation refuses
a package without them (inventory generation 10).

`THIRD-PARTY-NOTICES.txt` is generated by `koru-release` (`src/notices.rs`) for
the build it packages. It walks `cargo metadata` from the shipped binaries
through normal dependencies for the host platform, and copies each crate's own
license files. A crate without any uses its record in
`crates/koru-release/licences/crates/` (below), and **a crate with neither is a
refusal to package**. Fonts and the statically linked native libraries come
from `crates/koru-release/licences/bundled/`, one file per component with a
`Component/Version/Source/Files/License/Platforms` header; `Platforms` names
the builds that link it (`windows, macos, linux`, `macos`, `android`). Tests
hold that list to `FONTS`, to the Android faces in `scripts/setup/fonts.manifest` and
to `sherpa-onnx-sys`'s static libraries. To see the files without packaging:

```sh
cargo test -p koru-release generates_the -- --ignored
```

### A crate without a license file

Sixty-seven shipped crates, across every platform, publish no license file in
their crates.io package, and so does `selectors` 0.37.0, which ships once
something links `koru-diagram`.
Each has `crates/koru-release/licences/crates/<crate>.txt`: a header
(`Crate`, `Checked` — the version looked at, `License` — one the crate declares,
`Disposition`, `Source`, and `File` or `Issue`), `---`, then the text the
notices print.

- **`Disposition: upstream`** (57 crates, 2026-10-13 and -14): the license file from the
  crate's repository at the revision it was published from. The package's
  `.cargo_vcs_info.json` names that commit and the crate's path in the
  repository; fetch `https://raw.githubusercontent.com/<owner>/<repo>/<sha>/<path>`
  for the license the crate declares (the nearest one, from the crate's
  directory up to the repository root). A note says so when the published
  commit is not public or not recorded and an older, unchanged revision of the
  file was used.
- **`Disposition: judgment`** (11 crates): upstream has no license file at all.
  The text is the standard one, with the holder from the best evidence (a
  `COPYING` line, the Cargo authors, the repository owner), and `Issue` points
  at a request for a license file drafted in
  [UPSTREAM-ISSUES.md](UPSTREAM-ISSUES.md) for a maintainer to file.

A record must name a license its crate declares, or the generator refuses it.
It keeps applying across versions, labelled with the version it was checked
at; when a later release ships its own file, the crate's file wins and the
record can go. A new dependency without a license file stops `dist-local` and
`dist-cloud` with the crate's name; add its record the same way.

### Android

The APK carries `assets/licenses/`: `LICENSE.txt`, `NOTICE.txt`, `SOURCE.txt`
(`https://github.com/koruworks/mono/tree/<commit>`, from git at build time) and
`THIRD-PARTY-NOTICES.txt`. Gradle's `koruNotices<Variant>` task writes them
(`apps/android/app/build.gradle.kts`): it resolves the variant's runtime
classpath, collects each Maven library's POM licenses and the license files the
artifact carries (Google Play services' `third_party_licenses.*` among them),
and runs `koru-release notices android`. That adds the Maven libraries as a
third part to the same generator's crates (the `koru-mobile-native` graph for
both ABIs) and bundled components (`Platforms: android`). Apache-2.0 libraries
without files get the standard text; a library whose license needs a copyright
line and has no file uses `licences/maven/` (protobuf); Google's proprietary
Play services and ML Kit get a statement naming their terms; an unknown POM
license refuses the build. A debug build labels a crate without a record
`INFERRED` instead of failing; a release build refuses it.
`checkKoruNotices<Variant>` runs after `assemble<Variant>` and fails when the
APK lacks any of the four files. Settings → Open-source licenses shows them.

iOS does the same: `koru-release notices ios` writes the four files, an Xcode
build phase copies them into the app bundle (a Release build refuses an
unrecorded crate), and Settings → Open-source licenses shows them. It has not
been built on a Mac yet: [CATCHUP I18](../docs/features/macos/CATCHUP.md).

The same walk refuses a release when a shipped binary links a package marked
`LicenseRef-Koru-Proprietary`, the license the hosted services' packages
declare. No package in this repository carries it, and none is excused:
zero proprietary packages in a shipped graph is a release condition.

The packaged `NOTICE` is the repository's, followed by where that build's
source code is: `https://github.com/koruworks/mono/tree/<commit>`, the commit
`git rev-parse HEAD` reports for the packaged tree (MPL-2.0 §3.2). The channel
manifest carries the same link in its `source` field. An official package
refuses a tree whose commit it cannot name (`koru-release`, `src/source.rs`).

Voice-model packs carry their own `NOTICE.txt` (`src/voice/`), unchanged.

## In CI

`cargo-deny` (`deny.toml`, the `cargo-deny` check in `.github/workflows/ci.yml`)
holds every dependency to the licenses audited in
[THIRD-PARTY.md](THIRD-PARTY.md): the permissive licenses and MPL-2.0, with two
single-crate exceptions (`libbz2-rs-sys`, bzip2-1.0.6; `libfuzzer-sys`, NCSA).
GPL and LGPL are not on the list. A new license fails CI until this folder says
why it is acceptable and `deny.toml` allows it. The same check fails on RustSec
advisories; an exception names the advisory and the reason it does not apply.

The same workflow's repository checks run `scripts/checks/spdx-headers.py
--check`, so a first-party file without its header fails CI too.
